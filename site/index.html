dcsh

A mongosh-style REPL that drives the Discord REST API as your bot. REST-only, audit-logged, and safe by default.

Install GitHub npm 
# connect as a bot profile from your config
$ dcsh -p arkanis-main
arkanis-main> show servers
arkanis-main> use Arkanis
arkanis-main/Arkanis> show channels squad
arkanis-main/Arkanis> reason orphaned VC after sync bug
arkanis-main/Arkanis> await api.delete(Routes.channel('1234567890123456789'))
✓ deleted — audit reason: [dcsh:delta] orphaned VC after sync bug

Install

npm install -g @arkanis-corporation/dcsh

then run dcsh --help. Or without installing:

npx @arkanis-corporation/dcsh --help

Requires Node.js 22 or newer. You bring your own bot token — dcsh never ships one.

Safe by default

audit log

Every mutation needs a reason

POST/PUT/PATCH/DELETE require a reason, sent as [dcsh:operator] so manual fixes are distinguishable from bot behaviour in the audit log.

read-only

Read-only mode

Set per profile or with --read-only. Blocks all mutations and cannot be switched off mid-session.

no gateway

Never touches the gateway

dcsh only speaks REST, so it can't interfere with your running bot's session. It does share its rate-limit buckets.

no raw client

Only the guarded API

The token stays out of shell history and logs, and only the guarded api object is exposed — guarding against mistakes, not against a hostile operator.

What is it for?

When a bot leaves a channel orphaned, a role half-applied, or a message stuck, you often need to act as the bot to clean up — with the bot's permissions, against the real API. dcsh gives you an interactive shell for exactly that, with guard rails so a troubleshooting session doesn't become a second incident.
